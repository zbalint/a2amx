## 1. Why

`cs check src/confine/harness_data.rs` scores 7.07 with 14 findings (measured 2026-11-25 at `0320d19`): `harness_data` (`:17`, Bumpy Road, Complex Method cc 9, Large Method 78 lines), `harness_overlay_parents` (`:96`, 6 arguments), `overlay_protected_entries` (`:124`, cc 10, 7 arguments, and a Complex Conditional at `:143`), `validate_harness_data_paths` (`:200`, cc 11, 7 arguments), `ensure_data_files` (`:292`, Bumpy Road), `add_harness_data_mounts` (`:324`, Bumpy Road, nesting depth 4, cc 14, 6 arguments), and the file-level Overall Code Complexity. The owner's goal is a `cs`-clean repo, then `cs` as a gate in the pre-push script and CI; an agent never dismisses a finding.

The cause is shared, not local: the module spreads three kinds of loose state. The per-harness path table is restated in seven places (`harness_data`, `ensure_data_dirs:265-270`, `validate_harness_data_paths:209-214`, `ensure_data_files:293` for OMP, `add_harness_data_mounts:335-340`, `session_harness_root:383-389`, and `builder.rs` `effective_grants`, which the 3gy design read flagged as a carried-over duplication). The pair "data directories and data files" travels as two slices through three signatures (`overlay_protected_entries`, `validate_harness_data_paths`, `add_harness_data_mounts`) and the returned tuple; the data files alone go through `harness_overlay_parents` and `unsaved_harness_files`. The four path sets the plan has already decided (writable, hidden, read-only, protected) travel as four loose slices through both overlay functions.

Lessons that bind (from spec 3gy and earlier): a helper that exists only to clear a finding, or an out-parameter accumulator, is rejected at review; split only into contiguous runs so check order and first error stay; at most four parameters on every new function, `self` included; full `assert_eq` on texts and plan fields; a sort asserted over an empty list pins nothing; a test that removes the thing it is meant to fail on pins nothing; name every binding and import a removed parameter leaves unused (`-D warnings`).

Alternatives rejected: (1) moving the SQLite sidecar logic into its own module (one decision, three small helpers: not enough for a module; revisit if a second harness gets sidecars); (2) a trait per harness for the data tables (a `match` table is the whole variation; a trait is a shallow abstraction); (3) merging `harness_dir` into `Harness` in `src/harness.rs` (that module owns launch wiring, not confinement paths; changing it widens scope).
