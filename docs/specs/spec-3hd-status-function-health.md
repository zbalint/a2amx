- `enum Part { Team, Harness, Role, Quota, Activity, Pending, Hint, Remote, Confined }` (the order of `Shown::drop_next` today: team, harness, role, quota, activity, pending, hint, remote, confined) and `struct Shown(Vec<Part>)` holding the parts still shown, in that order: `Shown::all(parts: &Parts) -> Self` builds one table in drop order, `[(Part::Team, parts.team.is_some()), (Part::Harness, parts.harness.is_some()), (Part::Role, parts.role.is_some()), (Part::Quota, parts.quota.is_some()), (Part::Activity, parts.activity.is_some()), (Part::Pending, parts.pending.is_some()), (Part::Hint, parts.hold.as_deref().is_some_and(|reason| hint_allowed(reason, parts.prefix))), (Part::Remote, parts.remote.is_some()), (Part::Confined, parts.confine.is_some())]`, and keeps the present entries in that order (cyclomatic complexity 1: no nine-arm `match` over `Part`, which would move the ladder). `Shown` therefore always holds its parts in drop order, `fn has(&self, part: Part) -> bool` is a `contains`, and `fn drop_next(&mut self) -> bool` is `if self.0.is_empty() { false } else { self.0.remove(0); true }`.
