## 1. Why

A2AMX's later work (messaging, hooks, cross-host) sits on a host daemon that owns
PTYs, keeps terminal state while no human is attached, and lets a human attach,
detach, and switch sessions with the experience of running the harness directly.
This spec builds exactly that and nothing else: the terminal core. No messaging, no
MCP, no SQLite, no cross-host code, no harness-specific behavior.

The repo has a scaffold (module skeleton with `todo!()` bodies, pinned dependencies,
and seven failing emulator tests). Implement it test-first, one behavior at a time,
at the seams named in §10.

## 2. Design (read before any section below)

**D1. The daemon owns everything.** `a2amx daemon` is one foreground process with
a tokio runtime. It owns sessions; clients are thin. A session is one PTY, its
child, and its `Emulator`. Sessions live only as long as the daemon (no persistence
across daemon restarts in this spec).

**D2. The client redraws from the model, like tmux.** The daemon never forwards raw
PTY bytes to a client. The attach stream is: one full render of the session's
screen, then incremental renders derived from the emulator's damage tracking. Query
replies (DA, DSR) come only from the emulator and go to the PTY, never from the
client's outer terminal. Reattaching never replays historical side effects.
Consequences, all intended: no graphics, no hyperlinks, no clipboard writes, no
application-set window title, no bell reach the client. A2AMX sets the outer title.

**D3. One controlling attachment per session.** The attaching client's size becomes
the session size. A detached session keeps its last size and keeps running and
tracking terminal state.

**D4. Output is drained independently of clients.** A per-session reader thread
reads the PTY, feeds the emulator, and writes emulator query replies back to the
PTY. It never waits on a client. A slow client only delays its own attachment task:
damage accumulates in the emulator (bounded by screen size) and is rendered when the
client's socket accepts data. No per-client output queue exists.

**D5. Input is never dropped.** Client input goes into a bounded queue
(`tokio::sync::mpsc`, capacity 256 chunks) feeding one writer thread per session;
enqueueing awaits when full, applying backpressure to that client's connection. The
emulator's query replies use the same queue, so all PTY writes are serialized.

**D6. Blocking work stays off the async runtime.** PTY reads, PTY writes, and
dropping the PTY (`Pty` drop sends SIGHUP and blocks on the child) run on dedicated
`std::thread`s or `spawn_blocking`.

**D7. Security defaults** (from `AGENTS.md`): loopback listen by default; state dir
mode 0700; `admin.token` and `addr` mode 0600; every connection authenticates with
a `Hello` before anything else; tokens never appear in argv, logs, or errors.

## 3. `src/emulator.rs`

Keep `Emulator` as the only user of `alacritty_terminal::{term, vte, grid, event,
index}`. Config: `kitty_keyboard = false`, `scrolling_history = 10000`, other fields
default. Terminal identity is `TERM=xterm-256color` (set by the session, §6).

Change the scaffold types and methods as follows (everything not named is kept).

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum MouseMode { #[default] Off, Click, Drag, Motion } // DECSET 1000 / 1002 / 1003

pub struct Modes {            // replaces the scaffold struct; `mouse_reporting` is removed
    pub alt_screen: bool,
    pub bracketed_paste: bool,
    pub app_cursor: bool,
    pub app_keypad: bool,
    pub focus_reporting: bool,
    pub mouse: MouseMode,
    pub mouse_sgr: bool,      // DECSET 1006
}
// derives: Debug, Clone, Copy, PartialEq, Eq, Default

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Scroll { LineUp, LineDown, PageUp, PageDown, Top, Bottom }

impl Emulator {
    pub fn size(&self) -> Size;
    pub fn scroll(&mut self, scroll: Scroll);   // moves the viewport into history
    pub fn is_scrolled(&self) -> bool;          // viewport is above the live bottom
    pub fn render_full(&mut self) -> Vec<u8>;   // client-facing full redraw, resets damage
    pub fn render_update(&mut self) -> Vec<u8>; // client-facing incremental redraw, resets damage
}
```

Behavior:

1. `feed`, `resize`, `screen`, `snapshot` keep the scaffold contracts. `screen()`
   returns the **displayed viewport** of the active buffer; when the viewport is
   scrolled, `cursor.visible` is `false`. `Attrs::UNDERLINE` covers every underline
   variant. Query replies are the `Event::PtyWrite` strings alacritty emits, joined
   in order. `ColorRequest`, `TextAreaSizeRequest`, `ClipboardLoad`,
   `ClipboardStore`, `Title`, `ResetTitle`, `Bell`, and all other events are ignored
   (no reply, no effect): this is deliberate, see §11.
2. `snapshot()` is **self-contained** (a fresh emulator of the same size fed the
   snapshot reproduces `screen()`, including `modes.alt_screen`): when the alt
   screen is active it emits `ESC[?1049h` before drawing the alt viewport. It does
   not reset damage and takes `&self`.
3. `render_full()` produces what the attach client writes to its outer terminal
   after entering the outer alternate screen. It equals `snapshot()` except that it
   **never emits `?1049h` or `?1049l`** (the client stays in the outer alt screen
   regardless of the session's buffer). It resets the damage state and records the
   modes it emitted.
4. `render_update()` returns bytes that bring a client holding the previous render
   to the current state, and resets damage. It returns an empty `Vec` when nothing
   changed **or when `is_scrolled()`** (updates are paused while a viewport is
   scrolled; damage keeps accumulating and the next `render_full` covers it).
   Rules: for every damaged line, move the cursor to column 0 of that line, redraw
   the line's cells, clear the rest with `ESC[0m ESC[K`; a full-damage event
   (buffer switch, resize, scroll of the viewport) redraws every line; then set the
   cursor position and visibility; then emit only the mode changes since the last
   render (`render_full` or `render_update`). A line is drawn up to its last cell
   that is not a default blank (space, default colors, no attributes); skip
   `WIDE_SPACER` and leading-spacer cells; append zero-width combining characters
   after their base character. Each line begins from `ESC[0m` and each SGR change
   emits a complete SGR (reset then attributes and colors), so no state leaks
   between lines.
5. Both renders set the modes explicitly (DECSET/DECRST for bracketed paste, app
   cursor, app keypad `ESC=`/`ESC>`, focus reporting 1004, mouse 1000/1002/1003
   exactly one or none, SGR mouse 1006). They never emit OSC sequences, DCS,
   APC, or graphics.
6. `scroll` maps to alacritty's `scroll_display`. `Top` and `Bottom` jump to the
   oldest history line and the live bottom. Scrolling marks full damage
   (alacritty does this when the display offset changes) so the next `render_full`
   or an explicit redraw covers it. No-op scrolls change nothing.
7. `resize` keeps `Term` and any PTY resize consistent under one lock owned by the
   caller (§6); the emulator itself has no locking.

Shortcuts to leave as `// shortcut:` comments where they occur: soft-wrap flags
(`WRAPLINE`) are ignored (no reflow on the client), cursor style and blink are not
forwarded, mouse modes are collapsed to the four in `MouseMode`.

## 4. `src/prefix.rs`

Replace `todo!()` bodies and add one function:

```rust
pub fn parse_prefix(spec: &str) -> anyhow::Result<u8>;
```

`parse_prefix` accepts `C-space` (byte 0x00), `C-a`..`C-z` (0x01..0x1A,
case-insensitive), `C-\` (0x1C), `C-]` (0x1D), `C-^` (0x1E), `C-_` (0x1F), and
rejects everything else, including `C-i` (Tab), `C-j` (LF), `C-m` (CR), and `C-[`
(ESC), with an error naming the reason.

`PrefixMachine::feed` behavior:

1. A byte that is not the prefix, outside a bracketed paste, and not directly after
   a prefix is forwarded unchanged; adjacent forwarded bytes coalesce into one
   `Action::Forward`.
2. Prefix then `d` yields `Command::Detach`; then `w` yields
   `Command::SessionPicker`; then `[` yields `Command::ScrollMode`; prefix then
   prefix forwards one literal prefix byte; prefix then any other byte drops that
   byte (nothing is forwarded, no error).
3. State survives across `feed` calls: a prefix at the end of one read and the
   command byte at the start of the next is one command.
4. Inside a bracketed paste (`ESC[200~` … `ESC[201~`) every byte, including the
   prefix byte and `d`/`w`/`[`, is forwarded unchanged. Marker matching survives
   splits at every byte boundary. Bytes that might begin a marker are **forwarded
   immediately** (never held back); the machine only tracks how far into the marker
   it has matched. An unterminated paste stays in paste mode until the terminator.
5. The machine never delays or reorders forwarded bytes.

## 5. `src/wire.rs`

Framing is as scaffolded (`u32` big-endian length + payload, `MAX_FRAME_LEN =
1 MiB`). `encode_frame` errors above the limit. `FrameDecoder::push` returns every
complete payload, errors when a declared length exceeds the limit (before buffering
the payload), and tolerates reads split at any byte, including inside the length.

Change the control types to exactly these shapes (JSON as `serde` derives, tagged
by `type` in `snake_case`, as scaffolded):

```rust
pub enum Request {
    Hello { token: String },
    NewSession { argv: Vec<String>, cols: u16, rows: u16,
                 cwd: Option<String>, env: Vec<(String, String)> },
    List,
    Attach { session: String, force: bool, cols: u16, rows: u16 },
    Kill { session: String },
}
// Response, SessionSummary: unchanged from the scaffold.
```

Stream frames (after a `Response::Attached`, the connection carries only stream
frames, each inside the same length-prefixed framing). Payload = one tag byte then
the body:

| Frame | Tag | Body |
| --- | --- | --- |
| `ServerFrame::Data(Vec<u8>)` | `0x01` | the bytes |
| `ServerFrame::Exit(i32)` | `0x02` | 4 bytes big-endian |
| `ServerFrame::Detached(String)` | `0x03` | UTF-8 reason (new variant) |
| `ClientFrame::Input(Vec<u8>)` | `0x01` | the bytes |
| `ClientFrame::Resize { cols, rows }` | `0x02` | `u16` BE cols, `u16` BE rows |
| `ClientFrame::Detach` | `0x03` | empty |
| `ClientFrame::Redraw` | `0x04` | empty (new variant) |
| `ClientFrame::Scroll(Scroll)` | `0x05` | 1 byte: 0 LineUp, 1 LineDown, 2 PageUp, 3 PageDown, 4 Top, 5 Bottom (new variant; `Scroll` is `emulator::Scroll`) |

`decode` errors on an unknown tag, an empty payload, or a wrong body length. The
server never sends a `Data` frame above 64 KiB (it splits larger renders across
frames at any byte boundary); the client's `Input` frames never exceed 8 KiB.

## 6. `src/session.rs`

`Session::spawn(id, spec)` starts the child with `alacritty_terminal::tty::new`
(this module and `src/emulator.rs` are the only `src/` files that may name
`alacritty_terminal`). Requirements:

1. Command is the argument vector `spec.argv` (non-empty; empty is an error), cwd
   `spec.cwd`, environment = the environment given in `spec.env` (added to
   `SessionSpec`: `pub env: Vec<(String, String)>`) with `TERM=xterm-256color` and
   `COLORTERM=truecolor` set last so they win. Never `tty::setup_env()`.
2. A spawn failure (for example a nonexistent program) returns an error and leaves
   no session behind.
3. The master fd is used through two cloned handles (`try_clone`): one for the
   reader thread, one for the writer thread. The reader thread clears `O_NONBLOCK`
   with `rustix::fs::fcntl_setfl` and does blocking reads. Read error `EIO` (raw
   5) means end of output. The writer thread does blocking writes fed by the D5
   queue.
4. Resize is `rustix::termios::tcsetwinsize` on a cloned master fd, never
   `Pty::on_resize`. A failed resize is an error result, never a process exit.
   Resize and `Emulator::resize` happen together under the session lock (below).
5. Child exit is detected with `EventedPty::next_child_event` (poll on a short
   interval on a dedicated thread) yielding a wait status. Exit code = status >> 8
   when exited normally, or `128 + signal` when killed by a signal. The exit code
   becomes visible only **after** the reader thread has drained all remaining PTY
   output and fed it to the emulator (so the last screen is complete).
6. Shared state, one `Mutex` (the "session lock"): the `Emulator`, the current
   size, the exit code, and the attachment slot. A `tokio::sync::Notify` signals
   "emulator damaged or exit code set". The reader thread feeds under the lock,
   collects the replies, releases the lock, enqueues the replies for the writer,
   then notifies.
7. `kill()` sends `SIGHUP` to the child's process group (`rustix::process::
   kill_process_group`; the child is a session leader after `tty::new`, so its
   pgid is its pid), then `SIGKILL` to the group after 3 seconds if the child has
   not exited. Killing an already exited session is a no-op success.
8. Dropping a `Session` never blocks the runtime: the PTY is moved to a thread that
   drops it. Reader and writer threads end when the PTY closes.

Public additions: `SessionSpec::env`; `Session::notify() -> &Notify` and the small
accessors the daemon needs (size, attached flag, exit code). Keep everything else
private. Session ids are `s1`, `s2`, ... assigned by the daemon from a counter that
never reuses an id within one daemon run.

## 7. `src/daemon.rs`

**State dir** (`DaemonConfig::state_dir`; the CLI resolves `--home`, then
`A2AMX_HOME`, then `$XDG_STATE_HOME/a2amx`, then `$HOME/.local/state/a2amx`):

1. `Daemon::start` creates the dir (mode 0700, including missing parents at 0700)
   and takes an exclusive non-blocking `flock` on `daemon.lock` in it; failure to
   lock is the error `another a2amx daemon is running for this state dir`. The lock
   is held for the daemon's lifetime.
2. It binds every address in `listen` (a bind failure is an error and nothing
   stays bound), writes the bound addresses, one per line, to `addr` (mode 0600),
   and writes a fresh 32-byte random token, hex-encoded (64 characters), read from
   `/dev/urandom`, to `admin.token` (mode 0600), replacing any existing file.
3. `Daemon::addrs()` returns the bound addresses (resolving port 0).
   `Daemon::shutdown` stops accepting, disconnects attachments, kills every
   session (§6.7), removes `addr`, and releases the lock. `Drop` without `shutdown`
   must not hang.

**Connections.** Each accepted connection must send `Request::Hello` as its first
frame within 5 seconds with the exact admin token (compared without early exit);
otherwise the daemon sends `Response::Error` and closes. A valid hello gets
`Response::Ok`. Then the connection serves requests in order, one response each:

- `NewSession`: spawn per §6; `Created { session }` or `Error`. Empty `argv`,
  `cols` or `rows` of 0 are errors.
- `List`: `Sessions` ordered by numeric id ascending.
- `Kill { session }`: kill per §6.7 and remove the session from the registry once
  it has exited; `Ok`. Unknown id is `Error`. An exited session is removed at once.
- `Attach { session, force, cols, rows }`: unknown id or zero size is `Error`. If a
  controller exists and `force` is false: `Error` with the message `session <id> is
  attached elsewhere (use --force to take over)`. With `force`, the existing
  attachment receives `ServerFrame::Detached("taken over by another attachment")`
  and is closed first. Then resize the session to `cols`×`rows` (§6.4), reply
  `Attached`, and switch the connection to stream mode (§5).

**Stream mode**, one task per attachment, `select!` over: incoming client frames;
the session's `Notify`; a take-over signal.

1. First frame after `Attached` is `Data(render_full())`, taken under the session
   lock at the same instant the attachment is registered (no output falls between
   the snapshot and the first update).
2. On notify: lock, `render_update()` (empty while scrolled), unlock, send the bytes
   as `Data` (split per §5); if the exit code is set and no damage remains, send
   `Exit(code)` and close. The final `Data` is always sent before `Exit`.
3. `Input(bytes)` is enqueued per D5. `Resize` resizes the session under the lock
   then sends `Data(render_full())`. `Redraw` sends `Data(render_full())`.
   `Scroll(s)` calls `Emulator::scroll` and sends `Data(render_full())`. Live
   updates stay paused exactly while `Emulator::is_scrolled()` is true (§3.4), so
   they resume once a scroll reaches the live bottom. `Detach` frees the
   attachment slot and closes.
4. A closed or errored socket frees the attachment slot; the session keeps running.
5. A frame that fails to decode closes the attachment without harming the session.
   (An attachment to an exited session ends right after `Exit`, so `Input` and
   `Resize` never reach an exited session.)

Attaching to an already exited session succeeds: the client gets the final
`render_full` and then `Exit(code)`.

Logging uses `tracing`; never log the token, `Input` bytes, or PTY output.

## 9. `src/cli.rs` and `src/main.rs`

`main` becomes a tokio entry point. Errors print `a2amx: <message>` to stderr and
exit 1. Add to `Cli` a global `--prefix <KEY>` (env `A2AMX_PREFIX`, default
`C-space`, parsed by `parse_prefix`). Subcommands keep the scaffold shape.

- `a2amx daemon [--listen ADDR]...`: no `--listen` means `127.0.0.1:0`. Runs until
  SIGINT or SIGTERM, then `shutdown`. After binding it prints one line per address:
  `listening on <addr>` to stdout.
- `a2amx new [--detach] -- CMD ARGS...`: sends `NewSession` with the client's size
  (stdin `tcgetwinsize`, or 80×24 when stdin is not a terminal), current directory,
  and full environment. `--detach` prints the session id to stdout and exits 0.
  Otherwise it attaches; attaching with stdin not a terminal is the error `attach
  needs a terminal on stdin`.
- `a2amx list`: prints a header line `ID  STATE  ATTACHED  SIZE  COMMAND` then one
  line per session, columns padded to the widest value plus two spaces; STATE is
  `running` or `exited(<code>)`; ATTACHED is `yes` or `no`; SIZE is `<cols>x<rows>`;
  COMMAND is the argv joined by single spaces.
- `a2amx attach <session> [--force]` and `a2amx kill <session>` as scaffolded.

**Attach client.** On start: put stdin in raw mode (`rustix::termios`, restore on
every exit path including panic via a guard with `Drop`), write `ESC[?1049h`, the
title `ESC]2;a2amx: <id> BEL`, then apply frames. Terminal restore on exit, in
order: `ESC[0m`, reset of every input mode the render may have enabled
(`ESC[?2004l ESC[?1004l ESC[?1000l ESC[?1002l ESC[?1003l ESC[?1006l ESC[?1l ESC>`),
`ESC[?25h`, `ESC[?1049l`, restore termios. Then print one line to stderr:
`[detached from <id>]`, `[session <id> exited with code <n>]`, or
`[detached: <reason>]`. Exit status 0 in all three cases.

Data flow: read stdin (chunks up to 8 KiB) → `PrefixMachine` →
`Action::Forward` becomes `ClientFrame::Input`; `Command::Detach` sends `Detach` and
exits; `SIGWINCH` sends `Resize` with the new size; every `ServerFrame::Data` is
written to stdout unchanged.

**Scroll mode** (`Command::ScrollMode`): stdin is no longer forwarded. Keys:
`ESC[5~` PageUp, `ESC[6~` PageDown, `ESC[A`/`ESC OA` line up, `ESC[B`/`ESC OB` line
down, `ESC[H`/`ESC[1~`/`ESC OH` top, `ESC[F`/`ESC[4~`/`ESC OF` bottom, each sending
the matching `ClientFrame::Scroll`; `q` sends `Scroll(Bottom)`, sends `Redraw`, and
leaves scroll mode; all other keys are ignored. After writing each `Data` frame
while in scroll mode, the client overwrites the last row's right end with a
reverse-video `[scroll: q to exit]` and restores the cursor to hidden.

**Session picker** (`Command::SessionPicker`): stdin is not forwarded, incoming
`Data` frames are discarded (not written), a second control connection lists
sessions, and the client draws a full-screen list (header line
`a2amx sessions: Enter attach, Esc or q cancel, Up/Down or j/k move`, one row per
session in the `list` format with `>` on the selection and `(current)` on the
attached one). Keys: `ESC[A`/`k` up, `ESC[B`/`j` down, `\r` select, `q` or a read
that is exactly one `ESC` byte cancel. Cancel sends `Redraw`. Selecting the current
session cancels; selecting another sends `Detach`, attaches to it (no `--force`);
an attach error is shown on the footer row and the picker stays open.

Shortcuts to leave as `// shortcut:` comments: ESC-alone detection in the picker is
one-read based; the outer terminal title is not restored on exit.

## Amendment 2: child environment (§6.1)

OMP reported (correctly, verified against `alacritty_terminal-0.26.0`
`src/tty/unix.rs:229-241` and by a real PTY probe) that `tty::new` does not give the
child exactly `spec.env`: the child inherits the daemon's environment, the library
sets `ALACRITTY_WINDOW_ID`, `USER`, `HOME`, and `WINDOWID` first, then applies
`Options.env` (so supplied entries override those), and finally always removes
`XDG_ACTIVATION_TOKEN` and `DESKTOP_STARTUP_ID`.

Resolution: the pinned library's behavior is accepted, and it **replaces** the
"environment = the environment given in `spec.env`" clause of §6.1 with:

> The child's environment is the daemon's own environment overlaid with every
> `spec.env` entry (a supplied entry wins over an inherited or library-set one),
> with `TERM=xterm-256color` and `COLORTERM=truecolor` applied last so they win.
> The library-set `ALACRITTY_WINDOW_ID`, `WINDOWID`, `USER`, and `HOME` may appear
> when `spec.env` does not override them. `XDG_ACTIVATION_TOKEN` and
> `DESKTOP_STARTUP_ID` are removed by the library even if supplied; this is
> accepted and not worked around.

Consequences to implement and test, and nothing more: no `env_clear` workaround,
no wrapper program, no fork of or patch to the dependency. Leave a `// shortcut:`
comment at the `tty::Options.env` construction: variables present in the daemon
environment but unset in the client's stay visible to the child; upgrade to an
exact environment if a later spec needs isolation. The §10 daemon tests assert only
that supplied entries (for example `OUT`) reach the child and that `TERM` and
`COLORTERM` have the required values; no test may assert that a supplied
`XDG_ACTIVATION_TOKEN` or `DESKTOP_STARTUP_ID` arrives or that daemon-only
variables are absent. §9's "full environment" sent by `a2amx new` is unchanged.
§13 is unchanged.
