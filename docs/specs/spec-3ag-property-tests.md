## 1. Why

The pure modules have example tests only. Example tests pass for the inputs their author thought of. A property states a rule the documentation promises for every input and lets the generator hunt for a counterexample: framing that survives any read boundary, a prefix machine that ignores every byte inside a paste, a validator that cannot let a body forge an envelope. This is backlog F10 and the first step of the owner's goal of verifiable, non-slop quality.

The consultant's review (2026-10-15) also noted that `validate_message` rejects a body containing the closing tag `</a2amx-message>` but not one containing an opening tag `<a2amx-message id="m_`, and that `envelope_ids` matches that opening text (`src/messaging.rs:387` and `:502`). Section 4 pins what `envelope_ids` does with such a body today. Whether the validator should also reject it is a separate design decision (messages may legitimately quote the tag), not part of this spec.

## 2. Rules for every property

- The expected value comes from the documented contract, a literal, or an invariant. A documented metamorphic relation is allowed: a round-trip, split-invariance across read boundaries, or seed wrap. Computing the expected value with the same logic as the function under test is not. `parse_prefix` and `pick` may supply test INPUTS (valid prefix bytes, the name universe) but never the expected output.
- Test only through public items. No `#[cfg(test)]` access, no new `pub` in `src/`.
- Each file uses `ProptestConfig::with_cases(256)` unless a section says otherwise, and the whole file runs in under 10 seconds in a debug build (`cargo test --test prop_<name>`).
- Do not assert on the text of an error message; assert `is_err()` or the documented error `code`.
- A property that FAILS on the current code is a finding, not a defect of the test (none is expected). Do not change `src/` and do not weaken the property. Mark that one test `#[ignore = "finding: <one line>"]`, keep its shrunk counterexample in a comment above it as a literal, and report it in the completion message. The other tests still deliver. This is not a `BLOCKED`.

## 3. `tests/prop_wire.rs`

Contract sources: `src/wire.rs:1-5` (length-prefixed framing), `:14-23` (the limits), `:25-26` (`encode_frame`), `:42-52` (`FrameDecoder`: "tolerates arbitrary read boundaries", errors on a declared length above `MAX_FRAME_LEN` "before buffering the payload").

1. `frames_survive_any_read_boundaries`: for a generated `Vec<Vec<u8>>` of 0..8 payloads, each 0..=2048 bytes, concatenate `encode_frame(p)` for each, split the byte stream at generated cut points into chunks (a chunk may be empty), feed the chunks to one `FrameDecoder` in order and collect every returned frame. Expected: exactly the generated payloads, in order.
2. `encoded_frame_is_big_endian_length_then_payload`: for a payload of 0..=4096 bytes, `encode_frame` returns a vector whose first 4 bytes are the payload length as a big-endian `u32` and whose rest is the payload (module doc, line 1).
3. `oversized_declared_length_errors_before_payload`: for a declared length `n` generated from `MAX_FRAME_LEN + 1 ..= u32::MAX as usize`, feeding only the 4 header bytes to a fresh decoder returns `Err`.
4. `server_frames_round_trip`: for generated `ServerFrame::Data` (payload 0..=2048 bytes), `Exit(i32)` (any `i32`), `Detached(String)` (any string up to 256 chars), `decode(&frame.encode()) == frame`. `ServerFrame::Status` is out of scope.
5. `client_frames_round_trip`: for generated `Input` (0..=2048 bytes), `Resize { cols, rows }` (any `u16`s), `Detach`, `Redraw`, `Release`, and `Scroll` of each of the six `a2amx::emulator::Scroll` variants (`LineUp`, `LineDown`, `PageUp`, `PageDown`, `Top`, `Bottom`), `decode(&frame.encode()) == frame`.
6. `decode_never_panics_and_rejects_unknown_tags`: for arbitrary bytes 0..=64, `ClientFrame::decode` and `ServerFrame::decode` return a `Result` without panicking. The module doc at `src/wire.rs:3-5` is stale, so the tag table is the contract here: client `0x01` Input, `0x02` Resize (cols then rows, each `u16` big-endian), `0x03` Detach, `0x04` Redraw, `0x05` Scroll (one byte), `0x06` Release; server `0x01` Data, `0x02` Exit (`i32` big-endian), `0x03` Detached (UTF-8), `0x04` Status (JSON). An empty payload is `Err`; a first byte outside the table (client: not `0x01..=0x06`; server: not `0x01..=0x04`) is `Err`.
7. Plain `#[test]` boundary cases, not properties: `encode_frame` of exactly `MAX_FRAME_LEN` bytes is `Ok` and of `MAX_FRAME_LEN + 1` bytes is `Err`; `ClientFrame::decode` of an `Input` tag with `MAX_INPUT_LEN + 1` body bytes is `Err` and with `MAX_INPUT_LEN` is `Ok`; the same for `ServerFrame` `Data` and `MAX_SERVER_DATA_LEN`.

## 4. `tests/prop_messaging.rs`

Contract sources: `src/messaging.rs:9-12` (limits `MAX_SUBJECT_BYTES` = 200, `MAX_MESSAGE_BYTES` = 32768), `:360-390` (`validate_message`), `:409-423` (`render_envelope`), `:500-519` (`envelope_ids`: "Message sequence numbers of envelope tags, in first-appearance order"), `:330-355` (`parse_interval`: "a number followed by s, m or h, from 1s to 24h").

Generators: a SAFE SUBJECT is printable ASCII (`0x20..=0x7e`) with no `<` (the subject check rejects every control character, including `\n` and `\t`). A SAFE BODY is printable ASCII plus `\n` and `\t`, with no `<`. With no `<` the closing tag cannot occur, so these bases are accepted by `validate_message`.

1. `safe_content_within_limits_is_accepted`: SAFE SUBJECT of 1..=200 bytes and SAFE BODY of 1..=32768 bytes, `validate_message` is `Ok`. Use `with_cases(64)` for this one.
2. Each of these single-violation properties builds a valid base from (1) with headroom (SAFE SUBJECT of 1..=190 bytes, SAFE BODY of 1..=32700 bytes), because `validate_message` checks sizes before control characters and the closing tag, and breaks exactly one rule; the expected `Err` code is the documented one from the `code` module (`code::INVALID_CONTENT`, `code::TOO_LARGE`):
   - empty subject: `INVALID_CONTENT`; empty body: `INVALID_CONTENT`
   - subject of 201..=400 bytes: `TOO_LARGE`; body of 32769..=33000 bytes: `TOO_LARGE`
   - a control character other than `\n` and `\t` (any `char::is_control` code point) inserted at a generated position in subject or in body: `INVALID_CONTENT`
   - the literal text `</a2amx-message>` inserted at a generated position in the body: `INVALID_CONTENT`
3. `rendered_envelope_has_exactly_one_closing_tag`: for a `subject` from the FULL printable set (`0x20..=0x7e`, including `<`, `>`, `&` and `"`), a SAFE BODY, both accepted by `validate_message`, and a generated `from` (1..=40 characters of `a-z0-9@-.`), `render_envelope("m_7", from, subject, body)` contains `</a2amx-message>` exactly once and ends with it. The subject is escaped in an attribute (`<`, `>`, `&`, `"` become entities), so a subject cannot add a tag.
4. `envelope_ids_lead_with_the_envelopes_own_id`: for an id `m_<n>` with `n` in `1..=999999999`, a SAFE SUBJECT, a generated `from`, and a SAFE BODY, `envelope_ids(&render_envelope(...))` equals `vec![n]`. For the same inputs with a body that contains, at a generated position, one injected literal `<a2amx-message id="m_<k>"` where `k` differs from `n`, the result is non-empty, its first element is `n` (the envelope's own tag precedes its body; "first-appearance order"), and no value appears twice. This pins today's behavior; a body can add a second id to the list but cannot displace the first.
5. `intervals_parse_to_exact_seconds`: for `n` in `1..=86400`, `parse_interval(&format!("{n}s"))` is `Ok(Duration::from_secs(n))`; for `m` in `1..=1440`, `"{m}m"` gives `60 * m` seconds; for `h` in `1..=24`, `"{h}h"` gives `3600 * h` seconds.
6. `out_of_range_or_malformed_intervals_are_rejected`: `"0s"`, `"0m"`, `"0h"`, `"86401s"`, `"1441m"`, `"25h"`, `""`, `"s"`, `"5"`, `"5x"`, `"-5s"`, `"1.5s"`, `" 5s"` are all `Err` (plain `#[test]` over this literal list).

## 5. `tests/prop_prefix.rs`

Contract sources: `src/prefix.rs:1-6` (module doc: human input passes through untouched except the prefix; "Prefix twice sends a literal prefix"; "tolerates reads split at any byte and never interprets bytes inside a bracketed paste (`ESC[200~` ... `ESC[201~`)"), `:104-107` (`feed`: "Adjacent forwarded bytes are coalesced into a single `Forward`. State carries over to the next call").

Generators: the prefix byte is any `Ok` result of `parse_prefix` over the specs `"c-space"`, `"c-a"` to `"c-z"`, `"c-\\"`, `"c-]"`, `"c-^"` and `"c-_"` (skip the `Err` ones). Because `Forward` pieces split with the reads, every comparison below uses the NORMALIZED form: merge neighbouring `Action::Forward` values into one and keep `Action::Command` values in order.

1. `any_read_split_gives_the_same_actions`: for any prefix byte, input bytes 0..=64 drawn from a small alphabet that includes the prefix byte, `ESC`, `[`, `2`, `0`, `1`, `~`, `d`, `w`, `s`, `r` and arbitrary bytes, and any set of cut points, the normalized actions from feeding the chunks in order equal the normalized actions from feeding the whole input at once.
2. `input_without_the_prefix_is_forwarded_unchanged`: input of 0..=64 bytes that does not contain the prefix byte gives no actions when empty and otherwise exactly one `Forward` holding the input.
3. `prefix_twice_is_one_literal_prefix`: for single bytes `a` and `b` that are not the prefix byte, feeding `[a, prefix, prefix, b]` gives exactly one `Forward(vec![a, prefix, b])`.
4. `a_bracketed_paste_is_never_interpreted`: for any prefix byte and a body of 0..=64 bytes that contains no `ESC` byte (so the body cannot end the paste), feeding `ESC[200~` + body + `ESC[201~` to a fresh machine gives exactly one `Forward` holding all of those bytes and no `Command`; this includes bodies that contain the prefix byte followed by `d`, `w`, `[`, `s` or `r`.
5. Plain `#[test]`, literal table: prefix byte `0x02` followed by `d` gives `Command::Detach`, by `w` gives `SessionPicker`, by `[` gives `ScrollMode`, by `s` gives `StatusLine`, by `r` gives `Release`, each with a leading `Forward` of 0..=8 bytes fed before the prefix; those bytes exclude the prefix byte, `ESC` and the paste marker bytes.

## 6. `tests/prop_names.rs`

Contract source: `src/names.rs:134-135`: "First free `ADJECTIVE-NOUN` at or after `seed % 4096`, wrapping; `None` when all are taken."

Setup: the NAME UNIVERSE is `(0..4096).map(|i| pick(&[], i).unwrap())`; compute it once. Using `pick` here only builds inputs; assert the universe holds 4096 distinct strings (64 x 64 from the doc comment).

1. `seed_wraps_at_4096`: for any `u64` seed, `pick(&[], seed) == pick(&[], seed % 4096)`.
2. `a_pick_is_valid_and_not_taken`: for any seed and a `taken` list of 0..=50 strings drawn partly from the universe and partly arbitrary, a `Some(name)` result is not in `taken` and passes `a2amx::messaging::validate_name`.
3. `all_taken_gives_none`: a plain `#[test]` over the seeds `0`, `4095` and `u64::MAX`: `pick(&universe, seed)` is `None`. (One call scans about 16.7 million comparisons; it is not a proptest.)
4. `one_free_name_is_always_found`: for a generated index `i` in `0..4096` and any seed, with every universe name taken except `universe[i]`, `pick` returns `Some(universe[i].clone())`. Use `with_cases(8)`; the same cost applies.

## 7. `tests/prop_picker.rs`

Contract sources: `src/picker.rs:107-123` (`scroll_into_view`: "Keeps the selected row visible without jumping the window on every move"; "a visible window remains stable while the selection stays in view"), `:125-160` (`target`: "a clamped picker selection").

1. `scroll_keeps_the_selection_visible`: for `height` in `0..=60`, `total` in `0..=300`, `selection` in `0..total.max(1)` and any `offset` in `0..=400`, with `height > 0` and `total > height` the result `r` satisfies `r <= selection` and `selection < r + height`; with `total <= height` or `height == 0` the result is `0`.
2. `scroll_does_not_jump_when_the_selection_is_already_visible`: for the same ranges, when `offset + height <= total` and `offset <= selection < offset + height`, the result equals `offset`.
3. `navigation_targets_stay_in_range`: for `selection` in `0..=400`, `height` in `0..=60`, `total` in `0..=300` and `action` among `Move(d)` (`d: isize` in `-500..=500`), `Page(d)` (`d: isize` in `-5..=5`), `Home`, `End`: the result is `0` when `total == 0`, otherwise it is `< total`; `Home` gives `0`; `End` gives `total - 1`.
4. `moves_go_the_documented_way`: with `total > 0`, `Move(d)` with `d > 0` gives a result that is at least `selection.min(total - 1)`; `Move(d)` with `d < 0` gives a result that is at most `selection.min(total - 1)`; `Move(0)` gives `selection.min(total - 1)`.
5. `other_actions_leave_the_selection_alone`: for `total` in `1..=300`, `selection` in `0..total`, `height` in `0..=60` and `Cancel`, `Select`, `Toggle`, `Fold`, `Unfold`, `StartFilter`, `Char(c)` (any `u8`) and `Backspace`, `target` returns the `selection` argument unchanged.
6. `parser_never_panics`: for arbitrary bytes 0..=64 and each combination of `escape_alone` and `set_filter_mode(true|false)`, `PickerParser::feed` returns without panicking. No other `PickerParser` or `PickerView` property is in scope.
