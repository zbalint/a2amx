## 2. Changes (one step at a time; suite green after each; the byte stream is unchanged for every input)

0. Characterization first. The existing emulator tests mostly compare the mirror's screen, not bytes: they cannot see SGR order, the mouse-off order or an extra re-rendered line. The contract of this spec is the byte stream, so the new tests assert literal bytes with `assert_eq!` through `render_full` and `render_update` (written by hand, never produced by the function under test). Name the tests that pin `render_full`, `render_update` and the style, mode and cursor sequences (snapshot-style byte assertions) and adds, with literal expected bytes written by hand (never produced by the function under test), a passing test for each gap: for `public_cell` each of the nine flags alone and the combination (through the public `cells`/screen API the tests use today); for `append_cell_style` each flag's SGR parameter alone, a named colour below 16, 16 to 255, Rgb, and "all default" giving no sequence beyond the reset; for `append_mode_changes` every field changing alone from default, the keypad both ways, the mouse mode transitions (Off to each, each to Off, Click to Drag, with and without `explicit`); for `collect_damage` the synthetic cursor-cell damage ignored when neither cursor nor line changed, and kept when the cell under the cursor changed, when a combining mark was appended up to two columns left, and when the cursor moved; for `render_line` the literal cases: a blank line renders `CUP ESC[0m ESC[0m ESC[K` (the cursor-position sequence, then the reset at the start of the line, then the early-return reset and erase); trailing blanks give `ESC[K`; a wide character followed by its skipped spacer has no cursor-position sequence between them; a skipped cell forces one; a wide character in the last two columns gives no `ESC[K`; a style change mid-line. For styles: bold, dim, italic, underline, inverse, hidden and strikeout together give `ESC[0m ESC[1;2;3;4;7;8;9m` once; named foreground 1 with background 2 gives `38;5;1;48;5;2`; indexed 200 gives `38;5;200`; Rgb gives `38;2;r;g;b` and `48;2;r;g;b`; a bright named colour below 16; default colours and no flags give no SGR after the reset. For modes, from the default, one field at a time with `assert_eq!` on the update bytes: `2004`, `1`, `ESC=` and `ESC>`, `1004`, `1006`, Off to Click, Drag and Motion, Click to Drag (`ESC[?1000l ESC[?1002h`, in that order), Motion to Off (`ESC[?1003l` only), and an explicit `render_full` with mouse Drag (`?1000l ?1002l ?1003l ?1002h`). For `collect_damage`: nothing fed after `render_full` gives an empty update (the synthetic cursor damage is ignored); `A`, `ESC[D`, `ESC[1X` (the cell under the cursor changes) gives a line render; a combining mark on a base one and two columns left gives a line render; a cursor move alone gives no line render, only the cursor sequence.
1. `render_update`: remove the always-true `if has_damaged_lines || cursor_changed || modes_changed` and call `append_cursor` unconditionally (the early return already guarantees one of the three); `cursor_changed` is also computed inside `collect_damage` from the same values: pass it in as an argument instead of recomputing (equivalent); give the early-return condition one name if that removes the Complex Conditional (the developer checks with `cs check`; if it does not, say so and propose the next split). Same bytes for every input; the characterization of step 0 passes before and after.
2. `collect_damage`: extract the raw-cell-unchanged test (cursor, cell and the two preceding cells cache) into a private `&self` method, called BEFORE `self.term.damage()` (that call borrows `term` mutably for the whole `filter_map`); extract the synthetic-cursor-damage test as a free function over `(bound, raw_cursor, cursor_changed, raw_cell_unchanged)`, not a `&self` method (a method cannot borrow `self` while `damage()` holds `term`). Both are ANDs of pure reads, so the order of their terms is free. `self.term.reset_damage()` still runs exactly once, after `lines` is collected, and not at all on the scrolled path of `render_update`.
3. `render_line`: extract (a) the last non-default, non-skipped column scan returning `Option<usize>`; (b) the per-cell emit loop, which must return `output_col` or include the trailing `ESC[0m` and the conditional `ESC[K` (that test needs the final `output_col`). The order stays: cursor position and `ESC[0m` first, the scan, the blank-line early return, the emit loop, the trailing reset.
4. `public_cell` and `append_cell_style`: replace the `if` ladders with one private `const` table each (flag to attribute bit; flag to SGR parameter), never `pub` (the alacritty `Flags` type must not leak through a public item; the Semgrep rule excludes `src/emulator.rs`, so a private const there is fine). Every row is tested with `intersects`, not `contains`: `ALL_UNDERLINES` is a multi-bit set and `contains` would require all its bits. The SGR table keeps the present order (1, 2, 3, 4, 7, 8, 9, then foreground, then background; the reset is written first and the `count == 0` return comes after it); the attribute table's order is free (it ORs bits). A const union of flags needs `Flags::union` (the `|` operator is not const); check before using one.
5. `is_default_blank`: one private predicate for "default foreground and background" used by the condition; same result.
6. `append_mode_changes`: extract the keypad block and the mouse block as private functions in place (the emitted order stays: 2004, 1, keypad, 1004, mouse, 1006; inside the mouse block: explicit emits the three offs, otherwise the previous mode goes off if it was not Off, then the current mode goes on).
7. Run `cs check src/emulator.rs`; report each remaining finding with function and line.
